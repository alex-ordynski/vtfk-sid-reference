# `vtfk-sid-reference` — знімки ядра С.І.Д.

Публічний репозиторій знімків: **по гілці на ніч**, `after-lab01` … `after-lab09`.
Страховка для студента, який пропустив заняття, і сюжетно — копія, яку передає С.І.Д.

## Як цим користується студент

```bash
git clone -b after-lab04 <url> vtfk-sid
```

Далі рівні 2–3 виконуються на цьому знімку. **Оцінка така сама**, як за версію «на своєму
ядрі»: різниця не в складності, а в тому, звідки взято вхідні дані.

## Правила знімка

1. **Знімок — робочий стан, а не розв'язок.** У гілці `after-labNN` лежить лише те, що дає
   **рівень 1** ночі N. Коду рівнів 2–3 у знімку немає ніколи — інакше знімок стає готовою
   відповіддю на наступне завдання.
2. **Кожна гілка мусить збиратися.** Це перевіряє CI цього репозиторію (нижче), а не лінтер
   матеріалів: матеріали про знімки нічого не знають, крім імені гілки.
3. **Знімок оновлюється разом зі стартером.** Змінив стартер ночі 4 у `vtfk-materials` —
   перезніми гілку `after-lab04`. Каскад описаний у `vtfk-materials/CLAUDE.md` §3.2.
4. **`README.md` у кожній гілці — голосом С.І.Д.**, одним абзацом: «знімок тієї ночі, коли
   ми…». Це частина світу, а не службова примітка.

## Чому окремий репозиторій, а не тека `reference/` у шаблоні

Шаблон `vtfk-sid` роздається **один раз**, у ЛР1, а знімки з'являються впродовж семестру.
Classroom 50 не доносить оновлення стартера у вже прийняті репозиторії («starter code updates
are **not** pulled into accepted repositories»), тому донести знімок ночі 6 у шаблон, який
студент узяв у вересні, неможливо. Окремий репозиторій цієї проблеми не має: студент тягне з
нього коли завгодно. Рішення 37 плану апдейту, ADR 020.

## Чому публічний

Щоб `git clone` працював без токенів і без запитань. У знімку немає нічого, чого не видно в
методичці: це стан після **рівня 1**, а рівень 1 і так копі-паст за умовою.
